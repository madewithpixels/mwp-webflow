# Custom-code CSS audit — 12 Nov 2026

Question: which CSS in custom code (site/page head + footer, component embeds) can come back into the Webflow Designer, and which must stay in code?
Source: live Webflow custom code read 12 Nov (site head, site footer, Home head, Home footer) plus the Portfolio Nav component embeds.
Nothing has been changed in Webflow. Every Designer change below needs Michael's approval (D-006/D-007).

## 1. Project-page arrow navigation (the one Michael half-remembered)

Component: Portfolio Nav. Two `a.project-nav_arrow` (`data-portfolio-nav="prev|next"`).

The Designer classes `project-nav_arrow-prev` and `-next` already exist with the right left/right edge and corner radii, but are NOT applied to the arrows. Instead a component CSS embed does the same job with attribute selectors.

| Item | Where | Verdict |
|---|---|---|
| `[data-portfolio-nav=prev] {left:0; border-radius:0 25% 25% 0}` / `next` equivalent | component style embed | Move: apply `project-nav_arrow-prev` / `-next` to the arrows in the Designer, then delete these rules (R-112 part 2) |
| `a.project-nav_arrow {background:#ef8965; padding:0; animation:none}` (hover/focus-visible too) | component embed | Only exists to cancel the site-head conic-gradient rule that still lists `.project-nav_arrow`. Remove `.project-nav_arrow` from the site-head selector lists, then delete this |
| `.project-nav_inner, .grad-arrow-wrapper {border-radius:inherit}` | component embed | Designer: set radius on those classes (or inherit via the class variable) |
| `.bg-strip-wrapper {display:none}` | component embed | Dead elements: delete BG Strip Wrapper + 3 Grad BG Strip from the component, or set display none in the Designer |
| `img {-webkit-user-drag:none; user-drag:none}` (R-133) | component embed, but site-wide | Not a Designer property. Keep in code, but move out of the component into site head with a comment (it affects every image) |
| Site-head `.button,.instant-quote-btn,.project-nav_arrow {conic-gradient + spin-border}` | site head | Remove `.project-nav_arrow` from these selectors once the above is done |

After this: the component keeps only the script and the `img` rule (relocated).

## 2. Site head — can move to the Designer

| Rule | Designer route |
|---|---|
| `.folio-list li {margin-block:0}` | margin-top/bottom on the list item class |
| `.folio-list-link` background-repeat / position / size | background settings on that class |
| `.hero`, section classes `transition: filter .4s ease` | transition-property/duration/easing on each class |
| `.icon-arrow:hover/:focus .grad-bg-strip.segment-01/02/03 {background:var(--raspberry|coral|teal)}` (duplicated in Home head with !important) | Hover state on the strip classes; delete both code copies |
| `@media (min-width:1920px) .project-content-wrapper {align-self:end!important}` | align-self at the xl/xxl breakpoint |
| `.iwa-panel .mwp-result-panel {box-shadow:none; border-radius:none; border:none; padding:none!important}` | Plain Designer styles. NB `none` is invalid for radius and padding, so those two lines currently do nothing |
| `.menu-button:is(:hover,:focus-visible) .menu-button-label {max-width; margin-left; opacity}` at ≥768 hover | Partly: Designer can't do "child changes when parent hovers" without a combo/parent state. Candidate for a combo class (needs approval); otherwise stays |

## 4. Must stay in code

`@property --angle` and all `@keyframes` (spin-border, ticker-left/right, mwp-pt-safety), `@view-transition` and `::view-transition-*`/`view-transition-name` rules, `html.lenis.lenis-stopped` and `scrollbar-gutter` (R-081 header offset), `html.mwp-pt-*` state classes, `::marker` / `::-webkit-details-marker` (R-140), `color-mix()`, `clip-path`, mask gradients, `will-change`, `prefers-reduced-motion` blocks, `(hover:none) and (pointer:coarse)` variants, `env()` rules, Home testimonial-wall custom-property driven blur/mix/drop-shadow (set by JS and MWPPerf), `.mwp-nav-blur` (backdrop-filter toggled by script), Home ticker/promise `[data-mwp-sequence]` sticky/mask block, contents device (`.mwp-contents__*`, R-099/R-104), pricing `clip-path` block, and all JS-injected styles (folio-list hover highlight, preview element, hideBars, MWPPerf pills and lite CSS).

Borderline, could be Designer but drives off JS state class so stays tied to code: `html.mwp-folio-js .folio-list-link:hover/.is-hovered` (padding-left, background, italic). The values are Designer-mappable, but the selector depends on a JS-added class, so only movable if the JS toggles a real Designer class.
